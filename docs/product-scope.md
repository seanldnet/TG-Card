# TG-Card 产品功能范围与实施基线

> 产品定位：单商户、多 Telegram Bot 的自动发卡商城。所有商品、订单、库存、支付、售后与用户资产由同一套业务核心管理；Bot 是销售与服务入口，不是配置后台。

## 1. 总体原则

- 网页管理后台是唯一完整配置入口：商品、详情、价格、库存、机器人介绍、菜单、支付渠道、活动、售后规则均可在后台操作。
- 多 Bot 共用商品/库存/订单/用户/支付核心；支持全局默认配置和单 Bot 覆盖配置。
- Bot 菜单与商品列表由后台数据动态生成/同步，禁止要求管理员手工去 BotFather 添加业务菜单。
- 关键资金、库存、订单和卡密交付操作必须有数据库事务、幂等键、审计日志与并发保护。
- 金额使用最小货币单位整数存储，禁止使用浮点数进行金额计算。
- 当前产品保持单商户，不引入代理商/多租户分销体系。

## 2. 商城与商品管理

- 商品分类、商品增删改查、上下架、排序、搜索、标签、推荐/置顶。
- 商品详情：名称、封面图、图文介绍、使用说明、购买须知、售后说明、价格、原价、折扣、库存状态、限购规则。
- 商品类型：卡密自动发货、文本/账号密码类数字商品、人工交付商品；预留可扩展交付处理器。
- 卡密库存：批量导入/粘贴、去重、库存预警、批次管理、可售/锁定/已售/作废状态、导出权限控制。
- 商品规格/套餐、限购数量、每用户限购、库存不足提示、售罄状态。
- 商品详情、价格和库存变更后，所有绑定 Bot 的商城页面自动读取最新数据。

## 3. Telegram Bot 商城体验

- 多 Bot 管理：Token 安全保存、连接测试、启停、运行状态、Webhook/Polling 状态、Bot 用户名与头像信息。
- 后台配置欢迎语、商城介绍、客服入口、公告群、购买须知、用户信息展示。
- 模板变量：{telegram_id}、{username}、{first_name}、{balance}、{points}、{order_count} 等，发送时按当前用户替换。
- 后台可视化菜单管理：菜单项增删改、图标/名称、排序、启用状态、目标页面/命令/链接；自动生成 Inline Keyboard 与持久化 Reply Keyboard，按 Bot 能力适配。
- 推荐默认菜单：商城首页、商品分类、我的订单、我的余额、签到奖励、优惠券、申请售后、联系客服、业务公告、个人中心。
- 商品列表分页、商品详情、下单确认、支付状态查询、卡密查看/再次查看（受权限限制）。
- 用户首次进入自动建档；按 Telegram ID 识别用户，支持黑名单、备注、订单与售后历史。
- 群发公告/活动通知需支持预览、目标范围、频率限制、发送结果与失败重试。

## 4. 订单、支付与自动交付

- 订单创建、待支付/已支付/处理中/已交付/已关闭/退款中/已退款/售后中等状态机。
- 支付成功以服务端验签回调或链上确认结果为准；禁止仅凭前端跳转或用户截图标记已支付。
- 回调幂等、金额/币种/订单号校验、过期订单关闭、支付补单、对账记录。
- 支付成功后在事务内锁定并分配库存，确保同一张卡密不会重复售出；交付失败可安全重试且不重复扣库存。
- 自动交付结果通过 Bot 私聊发送；提供订单中心安全查看与再次获取入口。
- 支持订单备注、管理员手动补发/关闭/退款（按权限与审计策略控制）。

## 5. 售后与工单

- 用户从 Bot 菜单或订单详情发起售后申请，选择订单/商品、售后类型、问题描述并上传凭证。
- 售后类型可配置：未收到货、卡密无效、商品描述不符、重复扣款、其他问题。
- 售后状态：待受理、处理中、待用户补充、已解决、已拒绝、已关闭。
- 后台工单队列、优先级、负责人、内部备注、用户回复、图片/文件凭证、处理时限。
- 处理动作：补发卡密、重新交付、退款到站内余额、原路退款（支付渠道支持时）、拒绝并填写原因。
- 售后规则可按商品配置时间窗口、是否支持退款、自动/人工处理；保留完整操作流水。
- 用户可在 Bot 查询进度并收到状态变更通知。

## 6. 用户资产、签到与营销

- 用户余额账户、余额流水、充值/消费/退款/人工调整记录；所有变更记账且不可直接覆盖余额。
- 签到奖励：每日签到、连续签到、补签（可开关）、随机/固定奖励、积分或余额奖励、每日/每月上限、防重复领取。
- 积分系统：签到、活动赠送、消费奖励、积分兑换（后台配置规则）。
- 优惠券/兑换码：固定金额/折扣、适用商品、有效期、领取限制、使用门槛、叠加规则。
- 活动工具：限时折扣、满减、首单优惠、充值赠送、库存促销。
- 用户等级与消费统计；可选邀请有礼/推广码，但默认关闭，避免形成代理分销体系。
- 风控：异常频率限制、重复下单保护、黑名单、敏感操作二次确认。

## 7. USDT 与第三方支付

### 7.1 内置 USDT 收款

- 内置链上 USDT 收款适配器，网络、收款地址、最小确认数、订单超时、汇率/固定计价方式由后台配置。
- 首期收款网络已确定为 **TRON TRC20 USDT**；首期不开放 ERC20、BEP20 等其他网络，后续如需扩展必须新增独立链适配器。
- TRC20 主网 USDT 合约地址、精度、确认数和收款地址必须作为网络配置校验项；不得仅凭转账截图或未经确认的交易认定到账。
- 每笔订单生成唯一支付识别信息；优先使用独立收款地址或可验证的金额/备注策略，避免仅靠相同地址和相同金额误匹配。
- 链上交易监听、确认数跟踪、交易哈希去重、金额/网络/代币合约校验、到账后自动更新订单。
- 明确提示链上转账不可撤销、网络选择必须一致；提供人工核对与补单入口。
- 私钥不得明文存储或写入日志；优先使用只需收款权限的地址/观察钱包，不要求系统持有热钱包私钥。

### 7.2 GMpay 与 EPUSDT

- 提供独立 Provider Adapter：GMpay、EPUSDT，支付渠道参数由后台表单配置，不写死在代码或环境变量。
- 配置字段包括 API 地址、商户号、API Key/密钥、回调地址、启用状态、币种与网络选项；敏感值加密保存并脱敏展示。
- 创建支付订单、生成支付链接/二维码、服务端回调验签、金额与订单核对、幂等处理、主动查单、回调日志与失败重试。
- 测试模式/正式模式分离；支付渠道可单独启停。
- 具体签名算法、请求字段、回调格式必须严格按各服务商当前官方文档实现；不得猜测协议或伪造验签。

## 8. 后台管理模块

- 仪表盘：销售额、订单数、支付成功率、库存预警、待处理售后、用户增长。
- Bot 管理：Bot Token、欢迎介绍、菜单、公告、客服链接、运行状态。
- 商品中心：分类、商品、规格、价格、详情、库存、卡密批次。
- 订单中心：订单查询、支付详情、交付记录、退款/补发。
- 售后中心：工单分派、沟通、凭证、处理动作、状态跟踪。
- 用户中心：用户资料、余额/积分、订单、签到、优惠券、黑名单。
- 营销中心：签到规则、积分规则、优惠券、兑换码、促销活动。
- 支付中心：内置 USDT、GMpay、EPUSDT 的配置、测试、启停、回调日志、对账。
- 内容设置：欢迎文案、商城介绍、购买须知、公告、客服与群链接、菜单构建器。
- 系统设置：货币、时区、订单超时、库存策略、售后规则、安全策略、管理员、角色权限、审计日志。

## 9. 安全、可靠性与商业发行必备

- 管理后台登录、密码哈希、会话管理、RBAC 权限、登录限流、敏感操作审计。
- Bot Token、支付密钥、卡密内容加密存储；日志脱敏。
- Webhook 验证、请求签名、CSRF/CORS 策略、输入校验、速率限制。
- 数据库迁移版本化；Docker 默认 PostgreSQL；二进制版支持 SQLite 与 PostgreSQL。
- SQLite 使用 WAL、外键、忙等待设置；生产高并发场景推荐 PostgreSQL。
- 自动备份/恢复指引、健康检查、结构化日志、优雅关闭、任务失败重试。
- Docker 镜像和独立二进制由同一代码构建；提供 Linux AMD64/ARM64 发布包和校验值。
- 商业授权模块需支持授权码、机器指纹绑定、授权期限、版本权限与宽限策略；授权失败不得破坏已有订单/库存数据。

## 10. 交付优先级

### P0：可销售闭环
管理员初始化/登录、Bot 管理、后台欢迎语与菜单、商品分类/详情/价格、卡密库存、下单、支付、自动发货、订单查询、售后工单、审计日志、数据库迁移。

### P1：运营必备
签到奖励、余额与积分流水、优惠券/兑换码、公告群发、用户管理、库存预警、退款/补发、支付对账、统计报表。

### P2：增强能力
商品规格、促销活动、用户等级、邀请有礼（默认关闭）、自动风控、更多链上网络、更多支付 Provider、授权商业化管理。

## 11. 支付接入实施约束

内置链上 USDT 首期网络固定为 TRON TRC20。开发时必须校验 TRON 主网网络标识、官方 USDT TRC20 合约地址、代币精度、交易哈希、收款地址、实际到账金额和可配置确认数；同一交易哈希只能入账一次。不得把尚未达到确认数的交易标记为已支付。接入 GMpay 与 EPUSDT 前，必须取得并按官方文档核对其 API 基址、下单参数、签名算法、回调字段、查单接口和退款能力。文档不明确的字段不得自行臆造。

# 售后工单 MVP

- 用户在对应 Bot 私聊中使用 `/support 订单号 问题描述` 提交售后申请。
- 工单必须关联当前 Telegram 用户在当前 Bot 下的真实订单；未付款订单不能提交。
- 每笔订单同时只允许一个未关闭工单；已解决/拒绝/关闭后允许再次提交。
- 管理后台可查看最近 500 条工单，更新状态并填写管理员回复。
- 管理员回复会通过创建该工单的 Bot 私聊通知用户；Bot 未运行时回复仍保存在工单中，后台会记录通知失败。
- 状态包括 open、in_progress、waiting_user、resolved、rejected、closed；关键变更记录管理员审计。
- 当前版本不包含文件凭证、工单消息时间线、自动退款/补发工作流与 SLA 自动分派。
