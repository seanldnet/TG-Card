# 经营大盘指标

后台“经营概览”通过受保护的 `GET /api/dashboard/metrics` 获取聚合指标，避免为了展示汇总数字而下载全部订单明细。

## 指标定义

- 24 小时交付成功率：最近 24 小时内已付款且处于终态的订单中，`delivered / (delivered + delivery_failed)`。仍在交付或处于 `delivery_uncertain` 的订单不进入成功率分母。
- 待核实交付：当前 `delivery_uncertain` 订单数量、最早一笔的 `updated_at` 和等待秒数；另展示最近 24 小时新增的不确定订单数。
- 退款账本冲突：财务异常中心中 category 为 `refund_ledger` 且状态为 open/processing 的异常数量。
- 上游目录同步：展示当前同步任务状态、已处理/总项目数、当前页与错误数；无活动任务时显示最近持久化同步状态。
- Cap 验证成功率：当前应用进程启动以来的 Cap 服务端校验成功/失败计数。进程重启后计数归零；Cap 未启用或没有校验样本时显示“暂无样本”。
- API P95：最近最多 512 次 API 请求的内存采样 P95，排除 health 与 dashboard metrics 自身请求；进程重启后样本清空。
- 数据库连接池：来自 Go `database/sql` 的 open/in-use/idle/max-open 与等待计数/等待时长。

## 运行与安全边界

- 指标接口要求现有管理员 Bearer Token；不新增权限角色、环境变量或数据库迁移。
- 汇总 SQL 只读，不修改订单、资金流水、采购状态或异常状态。
- Cap 计数与 API 延迟采样为进程内指标，不是跨重启历史报表；如需长期趋势，应后续接入持久化指标或监控系统。
- 指标接口超时预算为 4 秒；前端可单独加载失败，不阻断机器人、商品、订单和售后基础概览。
